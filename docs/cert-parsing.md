# 증권 판독

증권 PDF에서 값을 뽑는 경로는 **세 갈래**입니다. 원본의 생김새가 셋 다 다릅니다.

| 경로 | 대상 | 방법 |
|---|---|---|
| ① 정규식 판독 | 국내 선체·전쟁 SCHEDULE, 클럽 가입증서, 컨테이너 | `pypdf` 텍스트 추출 + 정규식 |
| ② 이미지 판독 | **공제조합 증권 — 사실상 전부 스캔** | Gemini 비전 판독 (수동 실행) |
| ③ 공제액 절 판독 | 클럽 P&I·FDD 가입증서 | 전용 파서 (아래 참조) |

---

## ① 국내 SCHEDULE 양식 — 글자가 쪼개진다

국내 선체·전쟁 증권은 PDF에서 글자를 뽑을 때 **특정 글리프 앞에 공백이 끼어듭니다.**

```
AG REED VALUE          ← AGREED VALUE
PREMIUM AN D RATE      ← PREMIUM AND RATE
POLICY N O.            ← POLICY NO.
```

그래서 일반 정규식이 전부 빗나갑니다. **공백을 모두 지운 문자열**에 대고 찾으면 같은 양식에서
부보가액 93% / 보험료·기간 68% / 공제액 51%가 잡힙니다.

과거연도(2020~2023)는 보험료 엑셀이 없어 **이 경로가 사실상 유일한 금액 출처**입니다.

## ② 공제조합 증권 — 전부 스캔이다

2020~2026년 대상 339개 중 **333개가 텍스트 0**입니다. 정규식으로는 원리적으로 못 읽습니다.

- Gemini 비전으로 읽습니다.
- **증권을 외부로 보내는 작업이라 전체 재생성에 넣지 않았습니다.** 새 증권이 들어왔을 때만 수동 실행하고, **담당자 승인이 필요합니다.**
- 판독 결과는 캐시에 남아 두 번 읽지 않습니다. 재생성은 캐시만 가져다 씁니다.
- **실패한 판독은 캐시하지 않습니다** — 캐시해 버리면 영영 다시 시도하지 않습니다.

### 금액은 요율로 검산한다

조합 증권에는 요율이 적혀 있습니다.

```
PREMIUM AND RATE  USD 446.88  AND  0.1329%
```

그래서 `부보금액 × 요율 = 공제료` 가 맞는지 자동 확인합니다.
일시납·계속거래 **할인(5%·3%)은 정상**으로 봅니다.

!!! danger "할인율을 모르면 멀쩡한 값을 버립니다"
    처음에 할인을 모르고 검산했다가 **정상 616줄을 '검토필요'로 떨어뜨리고 부보가액을 비웠습니다.**
    산수가 안 맞는다고 값을 지우면 안 됩니다 — **증권값을 그대로 반영하고 목록에만 남깁니다.**

### 부보금액과 평가액이 뒤바뀌어 읽힌다

`AMOUNT INSURED`(조합 인수분)와 `INSURABLE VALUE`(선박 전체 평가액)는 다른 항목인데 AI가 가끔 혼동합니다. 요율로 계산해 자동으로 바로잡습니다.

### 배서·질권설정 서류는 첨부만

질권배서에는 **질권 잡힌 금액만** 적혀 있어 그대로 쓰면 부보액이 틀어집니다. 첨부는 하되 금액 출처로 쓰지 않습니다.

## ③ 클럽 공제액 — 양식이 네 가지다

!!! danger "하나만 보고 고치면 나머지 셋이 조용히 틀어집니다"
    이 파서는 하루에 **여덟 번** 고쳤습니다. 손대기 전에 네 양식을 전부 확인하세요.

| # | 양식 | 예 |
|---|---|---|
| A | 금액 뒤에 유형 | `USD 20,000 in respect of all cargo claims` |
| B | 유형이 제목 줄, 금액은 다음 문장 | `Cargo and general average` → `… deductible of USD 12,000 per voyage excluding legal…` |
| C | 표 (유형 → 금액 → 적용단위 → 제외) | `R34 Cargo  USD 12,000  Per voyage  Excluding` |
| D | 금액이 유형보다 **앞**, 통화는 줄 끝 | `Deductibles 15,000 All claims in respect of cargo, each single voyage.USD` |

그래서 문장 단위 판정으로는 안 됩니다. **금액마다 앞뒤 문맥을 보고 더 가까운 쪽**의 유형을 씁니다.
다만 두 군데를 반드시 잘라냅니다.

- **`excluding` 뒤** — '적용 제외' 설명입니다. 안 자르면 B·C가 전부 '법률비용'이 됩니다(실제로 425건이 그렇게 틀어졌습니다).
- **앞 문맥의 마지막 문장부호 이전** — D는 설명이 금액 뒤에 오므로, 안 자르면 직전 항목의 설명이 흘러들어와 화물/충돌이 뒤바뀝니다.

### 그 밖에 실제로 겪은 함정

| 증상 | 원인 | 대책 |
|---|---|---|
| 전부 '기본' 으로 잡힘 | `All claims in respect of cargo` 의 `All claims` 가 `cargo` 보다 가깝다 | **'기본'은 최후의 수단** — 구체적 유형이 하나도 없을 때만 |
| 표에서 유형이 다 날아감 | 창을 제목(`Crew - special deductible`) **뒤**부터 시작해 `Crew` 가 잘렸다 | 창을 제목 앞 80자부터 |
| 4건 → 1건 | 제목이 여러 번 나오는데 '첫 성공 창'을 썼다. 곁가지 하나만 걸린 창이 이겼다 | 창마다 판독해 **유형 붙은 게 많고 못 붙인 게 적은 창** 선택 |
| 절을 아예 못 찾음 | PDF 추출이 글자를 벌려 `DEDU CTIBLES` `U SD` | 전처리에서 되붙인다 |
| 86건 통째 실패 | 금액 뒤 `.Ship … Date of Entry` 가 제외어에 걸렸다 | 제외 판정은 **바로 붙은 문장까지만** |
| 다수 통째 실패 | `USD 10,000.` `US$ 20,000,` 처럼 문장부호가 붙는데 이를 막고 있었다 | 뒤에 **숫자**가 더 붙는 것만 거른다 |

유형을 못 붙인 금액은 `특별조건` 으로 남기고 **대표값 후보에서 뺍니다.**
대표값은 **기본 → 기타 → 최빈값** 순이며 `최저공제액`·`특별조건` 은 제외합니다.

## 증권을 레코드에 붙이는 규칙

- **선박 + 연도 + 보종** 이 맞아야 합니다.
- **보험자는 양쪽 다 알 때만** 일치를 요구합니다(폴더로 보험자를 알 수 없는 증권이 있습니다).
- 단 **공제조합·수협 줄에는 조합·수협 증권만** 붙입니다 (BR-9). 보험자를 모르는 증권까지 붙이면 본증권 금액이 조합 줄로 흘러들어갑니다.
- 로이드 PACKAGE 증권은 선체 줄과 전쟁 줄 **양쪽**에 붙습니다 (BR-12).

!!! example "선박명이 괄호 안에 있는 증권"
    일부 클럽 가입증서는 파일명이 `Certificate - 회사명(선박명) - (증권번호).pdf` 형태라
    **선박명이 괄호 안**에 있습니다. 괄호 안을 지우는 정규화를 그대로 쓰면 선명이 사라져
    **증권 252개가 통째로 미첨부**였습니다. 파일명 규칙으로 한 번 더 시도해 해결했습니다.
