# 재생성 파이프라인

전체 재생성은 명령 한 줄입니다. **순서가 중요합니다.**

```bash
python rebuild_all.py
```

## 12단계

| # | 단계 | 하는 일 | 순서가 중요한 이유 |
|---|---|---|---|
| 1 | 엑셀 → 레코드 | 연간보험료 엑셀(24~26PY) 파싱. **JSON을 새로 씀** | 항상 첫 번째 |
| 2 | 구 엑셀 판본 보완 | 옛 판본에만 있던 담보 채우기 | |
| 3 | 과거연도 생성 | 보험현황 시트 → 2020~2023 레코드 | **4번 앞이어야 함.** 과거 선박명이 로스터에 들어가야 옛 증권이 매칭된다 |
| 4 | 선박정보 보강 + **증권 PDF 첨부** | IMO·톤수·선종 보강, 선박×연도×보종으로 증권 연결 | |
| 5 | id 부여 | 빈 id 채우기 | |
| 6 | 인보이스 반영 | | |
| 7 | 계열사 보충 | 같은 선박의 계열사로 빈칸 채우기 | |
| 8 | 보험기간 규칙 적용 | BR-2 갱신일 규칙 | 증권 판독 **앞** — 증권이 이기게 |
| 9 | **증권 판독 → 값 적용** | 증권 우선(BR-1) | 첨부(4번) 뒤여야 함 |
| 10 | 공제조합 증권 반영 | 스캔 증권 판독 결과 적용 | 9번 뒤. 조합 증권 값이 최종으로 이겨야 한다 |
| 11 | 클럽 유형별 기초공제액 | BR-11 | |
| 12 | 컨테이너 보험 추가 | BR-4 | 맨 마지막. 선박 레코드와 무관 |

**소요시간**: 판독 캐시가 있으면 2~3분, 없으면 증권 약 4,100개를 다시 읽어 **20~30분**.
판독 로직을 바꿨을 때만 캐시를 지웁니다.

## 각 단계는 멱등이다

모든 스크립트는 단독 실행 가능하고, 여러 번 돌려도 결과가 같습니다.
일부는 `--dry-run` 으로 저장 없이 미리볼 수 있습니다.

!!! warning "단독 실행 뒤에는 그 뒤 단계가 안 돌아 값이 비어 있을 수 있습니다"
    특히 과거연도 생성을 단독 실행하면 그 레코드를 새로 만들므로 **증권 판독값이 날아갑니다.**
    의심되면 전체 재생성을 돌리세요(캐시가 있으면 빠릅니다).

## 재실행 식별자로 쓰면 안 되는 필드

!!! danger "`추출출처` 를 식별자로 쓰지 마세요"
    증권 판독 단계가 이 값을 `증권 우선(자동판독)` 으로 **덮어씁니다.**
    과거연도 생성이 이 실수를 했다가 **재실행 때 레코드 16건이 사라지는** 버그가 있었습니다.

    식별은 `서류종류` 로 합니다.

## 레코드 목록을 사전으로 다시 만들지 마라

!!! danger "실제 사고: 데이터 대량 소실"
    `{원본파일: 레코드}` 형태의 사전으로 병합한 적이 있는데, **증권이 안 붙은 레코드의
    `원본파일` 이 `None`** 이라 전부 한 칸으로 뭉개졌습니다.

    항상 기존 목록을 유지한 채 **찾아서 고치거나 뒤에 덧붙입니다.**

## 데이터를 건드렸으면 — 검증 체크리스트

```
□ 재생성 정상 종료
□ 총 레코드 수 · 연도 분포가 예상과 맞는가
□ id 중복 0 / 누락 0
□ 원본목록의 상대경로가 실제 파일로 존재하는가
□ 기존 연도 레코드 수 · 보험료 합계가 의도치 않게 바뀌지 않았는가
   → 바뀌었다면 "증권 우선"이 맞는 변경인지 확인하고 담당자에게 보고 (BR-1)
□ 스크립트 재실행 시 결과 동일한가 (멱등성)
□ 화면 · 엑셀 내보내기 · 공유용 HTML · 증권 열기 정상
□ 템플릿 JS 문법 검사
□ 설정 파일 값이 커밋에 섞이지 않았는가
```

작업 전 산출물 JSON을 백업해 두면 되돌리기 쉽습니다.
