## 알아 두면 좋은 우회법

### 저장소 세션이 끊긴다

파일서버(SMB) 세션은 유휴 시간이 지나면 서버가 끊습니다. 그 뒤 라이브러리가 세션을 **자기가 다시 만드는데**, 그때 자격증명이 없으면 익명으로 붙으려다 실패합니다.

→ 자격증명을 **매 호출에 넘깁니다.** 연결은 풀에 캐시되므로 매번 새로 접속하지는 않습니다.

### 선박 코드표는 지연 로딩

기동 시점에 네트워크를 타면 워커 부팅 타임아웃에 걸려 **워커가 죽고 앱 전체가 500**이 됩니다.
'처음 선박 조회를 할 때' 받아오도록 지연 로딩합니다.

### 조회할 때마다 9MB를 다시 읽던 문제

로컬 앱이 데이터 공급자를 주입하지 않아, 선박 조회 한 번에 **산출물 JSON을 매번 새로 파싱**했습니다(약 890ms). 게다가 매번 새 객체라서 선명 색인도 통째로 다시 만들어져 **색인이 무용지물**이었습니다.

→ 파일이 바뀔 때만 읽고 그 사이에는 **같은 객체**를 돌려줍니다. 약 **1.9ms**.

### 외부 API 호출은 연결 재사용

호출마다 새 연결을 맺으면 TCP+TLS 비용을 매번 뭅니다. 선박 조회는 회사 3곳에 차례로 물어보므로 그 비용을 세 번 뭅니다. 세션을 재사용해 **40~55%** 줄였습니다.
세션은 스레드 안전하지 않으므로 스레드별로 하나씩 둡니다.

### 스케줄이 나온 회사를 기억한다

선박 스케줄은 회사 세 곳에 차례로 물어 처음 나온 곳에서 멈춥니다.

!!! warning "계열사로는 회사를 못 맞힙니다"
    실측 결과 A사 소속 선박이 B사 코드에, C사 소속이 D사 코드에 있었습니다.
    **계열사 = 소유사, 회사코드 = 운항선사**라 서로 다릅니다.

    그래서 추측 대신 **한 번 맞힌 회사를 선박코드별로 기억**해 다음에 먼저 부릅니다.
