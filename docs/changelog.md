# 변경 이력

주요 변경만 적습니다. 상세는 코드 리포의 커밋·PR을 보세요.

## 2026-09

### 화면 성능
- **화면이 쓰는 필드만 브라우저로** 전송 — 레코드 JSON 8.19MB → 5.14MB (37%↓).
  가장 컸던 `원본목록`은 서버가 이미 가공해 함께 보내던 중복이었다.
- **첫 화면에서 표·통계를 비운다** — 조건을 걸거나 [전체 보기]를 눌러야 그린다.
  전송 후 화면 준비 4,332ms → 116ms.
- **조건검색을 Enter/[검색] 버튼 실행으로** — 글자마다 표 전체를 다시 그리던 것을 없앴다.
  같은 입력의 처리량 1/1,469.

### 선박 조회
- 산출물 JSON을 조회마다 다시 읽던 것을 파일 캐시로 — 888ms → 1.9ms.
- 선박 코드표 메모리 캐시, 선명 색인 도입.
- 외부 API 호출 연결 재사용 — 40~55%↓.
- 스케줄이 나온 회사를 선박별로 기억해 다음 조회 때 먼저 호출.

### 사고 유형별 기초공제액 (BR-11)
- 클럽 증권의 공제액을 유형별로 판독해 **팝업**으로 제공(증권 원문 포함).
- 공제액 파서 전면 개정 — 증권 1,594개 기준 **새로 읽음 521 · 항목 교정 241 · 손실 0**.
- 공동인수 프로그램(BR-10) 분리 — 증권 두 장 모두 첨부, 공제액은 1차 인수사 기준.
- 로이드 PACKAGE 증권을 선체 줄에도 첨부 (BR-12) — 첨부 94건 증가.

### 고친 버그
- 공제조합 줄에 본증권이 붙어 공제료가 20배로 잡히던 것 (BR-9).
- 클럽 가입증서 252개가 통째로 미첨부 — 선박명이 괄호 안에 있어 정규화가 지워버렸다.
- 선명 주석 때문에 한 배가 세 척으로 잡혀 보험료가 이중계상되던 것 (BR-6).

### 배포
- 사내 컨테이너 환경으로 이전. 저장소를 **사내 NAS(SMB)** 로 전환 — 증권이 사외로 나가지 않는다.
- GitHub Actions 자동 배포.
- 코드 리포를 조직 계정으로 이전.
