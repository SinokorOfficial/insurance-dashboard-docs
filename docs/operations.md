# 갱신 절차

## 새 증권이 들어왔을 때

```text
   ①                      ②                    ③
   작업 원본 폴더에  ──▶   재생성        ──▶    게시            ──▶  웹에 반영
   증권·엑셀 넣기          rebuild_all.py       저장소에 반영
                          (캐시 있으면 2~3분)   ← 아직 수동
```

| 단계 | 지금 상태 |
|---|---|
| ① 원본에 넣기 | 담당자 또는 다른 담당자가 파일서버에 업로드 |
| ② 재생성 | 명령 한 줄. 캐시 있으면 2~3분 |
| ③ 게시 | **아직 수동** — 개선 대기 |

!!! warning "저장소가 두 곳으로 갈라져 있습니다"
    재생성이 읽는 **작업 원본**과, 웹이 읽는 **게시본**이 서로 다른 파일서버에 있고
    **자동 동기화가 없습니다.** ③을 버튼 하나로 묶는 것이 남은 과제입니다.

## 스캔 증권이 새로 들어왔을 때만

공제조합 증권은 스캔이라 별도 경로입니다. **자동 파이프라인에 없습니다.**

```bash
python read_ksa_certs.py     # 새로 들어온 것만 이미지 판독 (30~60분)
python apply_ksa_certs.py    # 판독 결과 반영
```

- 판독 결과는 캐시에 남아 **두 번 읽지 않습니다.**
- **증권을 외부 API로 보내므로 담당자 승인이 필요합니다.**
- 무엇이 바뀌었는지는 보고서 파일에 전부 기록됩니다
  (`변경` = 기존 값이 증권으로 바뀐 것, `공제료차이` = 증권과 엑셀 금액이 다른 것,
  `신규레코드` = 증권만 있어서 새로 만든 줄).

## 값이 이상할 때

1. **증권을 먼저 봅니다** (BR-1). 표의 📎 링크로 원본을 엽니다.
2. 증권이 맞고 데이터가 틀렸으면 → 화면에서 **직접 수정**(BR-7). 출처가 `직접수정` 으로 남습니다.
3. 판독 로직 문제로 보이면 → 판독 캐시를 지우고 재생성합니다.

!!! danger "산수가 안 맞는다고 값을 지우지 마세요"
    요율 검산이 안 맞는 건은 **증권값을 그대로 반영하고 목록에만 남깁니다.**
    중도가입·분납·할인 때문에 정상적으로 안 맞는 경우가 있습니다.

## 담당자 확인이 필요한 항목

자동으로 정하지 않고 **보고만 하는** 것들입니다.

| 항목 | 왜 자동으로 못 정하나 |
|---|---|
| MII / MAP 분리·합체 기준 | 업무 판단. 임의로 합치거나 분리하지 않는다 |
| 로이드 PACKAGE 증권의 선체 부보금액 | 증권 합계와 엑셀값이 다르다 (BR-12) |
| 클럽 대표 기초공제액 | 어느 유형을 표에 보일지 (BR-11) |
| 같은 배·같은 해에 정식 증권이 두 장인데 금액이 다른 건 | 중도 선주변경·재발행 — 어느 장이 맞는지 |
